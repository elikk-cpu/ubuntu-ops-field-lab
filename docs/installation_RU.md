
# LAB 01 — Установка и подготовка окружения

## 1. Назначение

Документ описывает процесс воспроизведения инфраструктуры Ubuntu Server, используемой в LAB 01.

Лабораторный стенд разворачивается локально в VMware Workstation без необходимости использования платных облачных сервисов.

Установка создаёт базовое окружение для дальнейшего изучения администрирования Linux, управления доступом, LVM, systemd и диагностики неисправностей.

## 2. Предварительные требования

Необходимые компоненты:

- Хостовая операционная система Windows
- VMware Workstation 25H2
- ISO Ubuntu Server 24.04.5 LTS (AMD64)
- Доступные ресурсы: 2 vCPU, 2 ГиБ RAM и 32 ГБ суммарной виртуальной дисковой ёмкости
- SSH-клиент на Windows

Установочный ISO был получен из официального репозитория Ubuntu.

Перед установкой необходимо проверить целостность образа, сравнив SHA256 с официальным файлом SHA256SUMS.

Это позволяет обнаружить повреждение или несоответствие скачанного образа.

## 3. Конфигурация виртуальной машины

Создание виртуальной машины выполняется через мастер VMware Workstation с ручным выбором параметров.

| Параметр | Значение |
|---|---|
| Имя VM | ubuntu-ops-01 |
| Гостевая ОС | Ubuntu 64-bit |
| Режим загрузки | Legacy BIOS |
| Процессор | 2 vCPU |
| Оперативная память | 2048 MB |
| SCSI-контроллер | LSI Logic |
| Системный диск | 20 ГБ |
| Дополнительный диск 1 | 6 ГБ |
| Дополнительный диск 2 | 6 ГБ |
| Основная сеть | VMnet10 — NAT |
| Сеть управления | VMnet11 — Host-only |

Все виртуальные диски подключены по интерфейсу SCSI.

Для файлов виртуальных дисков не используется предварительное выделение всего пространства.

Размер системного диска составляет 20 ГБ вместо предусмотренных исходным техническим заданием 18 ГБ.

Это документированное отклонение не препятствует выполнению требований лабораторной.

## 4. Настройка виртуальных сетей VMware

### 4.1 NAT — VMnet10

Параметры сети:

- Тип подключения: NAT
- Подсеть: `10.50.0.0/24`
- DHCP VMware: включён
- Виртуальный адаптер Windows: подключён

Первый сетевой адаптер VM необходимо явно привязать к VMnet10 через параметр Custom: Specific virtual network.

Во время установки Ubuntu получила адрес `10.50.0.128/24` через DHCP.

Адрес не является гарантированно постоянным и может измениться при обновлении DHCP-аренды.

NAT предназначен для исходящих подключений, установки пакетов и обновлений.

### 4.2 Management — VMnet11

Параметры сети:

- Тип подключения: Host-only
- Подсеть: `172.28.50.0/24`
- DHCP VMware: отключён
- Виртуальный адаптер Windows: включён

Второй сетевой адаптер VM необходимо явно привязать к VMnet11.

IP-адрес Windows в management-сегменте:

`172.28.50.1/24`

Host-only используется для административных подключений к серверу.

Данная сеть не требует маршрута в интернет.

## 5. Установка Ubuntu Server

Виртуальная машина загружается с официального установочного ISO Ubuntu Server.

Выбирается стандартная установка Ubuntu Server, а не Ubuntu Server (minimized).

Дополнительные Featured Server Snaps не устанавливаются.

### 5.1 Разметка дисков

Для установки выбирается системный диск `/dev/sda` размером 20 ГБ.

Используется автоматическая разметка с отключённым LVM для системного диска.

Установщик создаёт:

- BIOS boot partition размером около 1 МБ
- Корневую файловую систему ext4 с точкой монтирования `/`

Дополнительные диски `/dev/sdb` и `/dev/sdc` остаются неразмеченными.

Они предназначены для последующего создания отдельного LVM-хранилища.

Такое разделение позволяет экспериментировать с LVM без изменения корневой файловой системы ОС.

### 5.2 Первоначальный пользователь

Во время установки создаются:

- Имя сервера: `ubuntu-ops-01`
- Имя администратора: `ubuntu`
- Метод аутентификации: локальный пароль

Пароли не записываются в документацию и не публикуются в Git.

Пользователь `ubuntu` входит в группу `sudo`, что позволяет выполнять административные операции с повышением привилегий.

### 5.3 Установка SSH

Во время установки выбирается Install OpenSSH Server.

Для первоначального подключения временно разрешена аутентификация по паролю.

В следующих этапах предусматриваются:

- Создание SSH-ключей
- Настройка доступа по публичному ключу
- Проверка успешной аутентификации
- Отключение парольного SSH-доступа
- Проверка запрещённых способов входа

Отключать парольную аутентификацию до проверки доступа по ключам нельзя, поскольку это может привести к потере удалённого доступа.

## 6. Настройка статического management IP

Ubuntu Server использует Netplan для управления сетевыми настройками.

Создаётся файл:

`/etc/netplan/90-management.yaml`

Содержимое файла:

```yaml
network:
  version: 2
  ethernets:
    ens34:
      dhcp4: false
      addresses:
        - 172.28.50.10/24
      optional: true
```

### 6.1 Права доступа

Для ограничения доступа к конфигурации выполняется:

```bash
sudo chmod 600 /etc/netplan/90-management.yaml
```

Права `600` позволяют владельцу читать и изменять файл, запрещая доступ остальным пользователям.

### 6.2 Проверка конфигурации

Проверка синтаксиса:

```bash
sudo netplan generate
```

Пробное применение с возможностью отката:

```bash
sudo netplan try --timeout 120
```

После подтверждения сохранения сетевой доступ должен продолжить работать.

Для `ens34` не задаётся шлюз по умолчанию.

Это предотвращает появление конкурирующего default route и сохраняет основной выход через NAT-интерфейс `ens33`.

## 7. Первоначальная проверка

### 7.1 Проверка ОС

```bash
cat /etc/os-release
```

Команда позволяет определить установленный дистрибутив, его версию и кодовое имя.

Подтверждена Ubuntu Server 24.04.5 LTS.

### 7.2 Проверка дисков

```bash
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS
```

Проверяются:

- Системный диск `/dev/sda`
- Корневая файловая система ext4
- Два дополнительных диска по 6 ГБ
- Отсутствие разделов на дополнительных дисках

### 7.3 Проверка сети

```bash
ip -br addr
ip route
```

Подтверждённая адресация:

- `ens33` — `10.50.0.128/24`
- `ens34` — `172.28.50.10/24`

Маршрут по умолчанию:

`default via 10.50.0.2 dev ens33`

Management-маршрут:

`172.28.50.0/24 dev ens34`

### 7.4 Проверка SSH

Проверка состояния службы:

```bash
systemctl is-active ssh
systemctl is-enabled ssh
```

Проверка подключения с Windows:

```powershell
ssh ubuntu@172.28.50.10
```

SSH-подключение с Windows было успешно подтверждено.

После перезагрузки проверены состояние SSH и сохранение настроек сетевых интерфейсов.

Доступ в интернет и к внешним репозиториям пакетов требует отдельной проверки.

## 8. Контрольная точка восстановления

Для начального состояния предусмотрен VMware Snapshot:

`LAB01-01-Clean-OS-Network-SSH`

Он предназначен для возврата к работоспособному состоянию после установки ОС и настройки сети.

Создание и наличие Snapshot должны быть подтверждены в VMware Snapshot Manager до отметки данного требования как выполненного.

Snapshot не является полноценной независимой резервной копией, поскольку зависит от файлов виртуальной машины и хостового хранилища.

## 9. Известные ограничения

- Используется одна VM без высокой доступности.
- Парольная SSH-аутентификация пока не отключена.
- Отдельное LVM-хранилище ещё не создано.
- Доступ к внешним пакетным репозиториям требует отдельной проверки.
- Дополнительные меры безопасности и разграничения полномочий ещё не выполнены.
