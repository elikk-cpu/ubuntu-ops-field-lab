# Ubuntu Operations Lab — DevOps-портфолио

[English](README.md) | [Русский](README_RU.md)

Практический проект по администрированию Linux-инфраструктуры на основе Ubuntu Server 24.04.5 LTS и VMware Workstation.

Лабораторная работа демонстрирует администрирование Linux, сетевую безопасность, разграничение доступа, управление хранилищем и службами, диагностику производительности и реагирование на инциденты.

## Статус проекта

**LAB 01 — техническая реализация и испытания завершены.**

Финальная проверка документации и публикация в GitHub находятся в процессе.

Заключительная проверка инфраструктуры выполнена 2026-10-14.

## Обзор инфраструктуры

| Компонент | Реализация |
|---|---|
| Гипервизор | VMware Workstation |
| Операционная система | Ubuntu Server 24.04.5 LTS |
| Виртуальная машина | `ubuntu-ops-01` |
| Ресурсы | 2 vCPU, 2 GiB RAM |
| Сеть | NAT + выделенная Host-only сеть управления |
| Удалённое администрирование | OpenSSH с ключами Ed25519 |

| Разграничение доступа | Linux DAC, группы, SGID, sudo |
| Хранилище | LVM с ext4 |
| Приложение | HTTP API на Python для проверки состояния |
| Управление службами | systemd |
| Мониторинг | systemd-таймер проверки состояния |

## Сетевая архитектура

Виртуальная машина использует два сетевых интерфейса:

- **ens33:** VMware NAT для исходящих сетевых подключений.
- **ens34:** Host-only сеть управления, `172.28.50.10/24`.

Компьютер Windows подключается к Ubuntu через выделенную сеть управления с адреса `172.28.50.1`.

SSH-доступ ограничен авторизованными подключениями из сети управления. HTTP API прослушивает только `127.0.0.1:8080` и недоступен напрямую из внешних сетей.

Подробнее: [Архитектура](docs/architecture_RU.md).

## Реализованные возможности

### 1. Разграничение доступа Linux

- Созданы отдельные учётные записи `developer` и `operator`.
- Настроены группы для разработки и операционных задач.
- Реализованы права каталогов и наследование группы через SGID.
- Успешно выполнены восемь положительных и отрицательных DAC-тестов.
- Проверены umask `0002` и более строгий umask `0007`.
- Подтверждена защита системной конфигурации от несанкционированных изменений.
- Права sudo для оператора ограничены конкретной командой перезапуска API.

### 2. Безопасность SSH и межсетевой экран

- Настроена аутентификация по открытому ключу Ed25519.
- Отключена парольная аутентификация SSH.
- Запрещён прямой вход root по SSH.
- Для UFW настроено правило deny по умолчанию для входящих подключений.
- Административный SSH разрешён только через сеть управления.
- Проверены разрешённые и запрещённые подключения.
- Подтверждено сохранение настроек после перезагрузки.

### 3. Работа с LVM-хранилищем

- Создана группа томов LVM на дополнительных виртуальных дисках.
- Создан и смонтирован логический том с файловой системой ext4.
- Логический том расширен онлайн примерно с 6 GiB до 12 GiB.
- Настроено постоянное монтирование.
- Целостность данных проверена с помощью SHA256.
- Доступность хранилища подтверждена после перезагрузки.

Подробнее: [Работа с хранилищем](docs/storage_RU.md).

### 4. Управление службами systemd

- HTTP API на Python развёрнут как служба systemd.
- Для службы используется отдельная непривилегированная учётная запись.
- Применены ограничения безопасности systemd.
- Настроено автоматическое восстановление после аварийного завершения процесса.
- Проверены разрешённый перезапуск службы и её восстановление.
- Подтверждён автоматический запуск после перезагрузки.
- Добавлена периодическая проверка состояния через systemd timer.

Адрес проверки состояния: `http://127.0.0.1:8080/health`

Пример ответа:

```json
{"status": "ok", "service": "ubuntu-ops-api"}
```

Подробнее: [Работа с systemd](docs/systemd_RU.md).

### 5. Диагностика производительности

Выполнены контролируемые практические проверки:

- Загрузка CPU и системная нагрузка (load average).
- Использование оперативной памяти.
- Активность swap.
- Операции чтения и записи на диск.
- Заполненность файловой системы и использование inode.

Испытания проводились в лабораторном окружении VMware и не являются производственными бенчмарками.

### 6. Реагирование на инциденты

Воспроизведены и устранены три контролируемых инцидента.

| ID | Инцидент | Первопричина | Результат |
|---|---|---|---|
| INC-01 | HTTP API недоступен | Явная остановка службы через systemd | Устранён |
| INC-02 | Permission denied | Недостаточные права записи в файл | Устранён |
| INC-03 | No space left on device | Исчерпание блоков данных файловой системы | Устранён |

Для каждого инцидента подготовлены RCA-отчёты на английском и русском языках.

## Быстрая проверка состояния

Выполните внутри виртуальной машины Ubuntu:

```bash
systemctl is-active ubuntu-ops-api.service
systemctl is-active ubuntu-ops-healthcheck.timer
curl -fsS http://127.0.0.1:8080/health
df -hT /srv/ubuntu-ops/data
```
